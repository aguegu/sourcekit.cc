# MeshMass 可编程遥控系统

**官方在线平台：**
- **全球访问**：[meshmass.com](https://meshmass.com)
- **中国大陆访问**：[meshmass.y77.cc](https://meshmass.y77.cc)

## 概述

MeshMass 是一系列经济实惠的可编程遥控模块，专为遥控爱好者、STEM教育和3D打印社区设计。该系统包括：

- **TX6A4D 发射器**：带双摇杆、旋转旋钮和按钮的可编程控制器
- **RX4M4S 接收器**：4通道直流电机 + 4通道舵机接收器，内置电机驱动

它们共同构成一个完整的无线控制系统，填补了复杂的开源硬件解决方案和昂贵的专有遥控系统之间的空白。

## 缘起

MeshMass 的起点不是电子，而是 3D 打印模型。

陈东浩——在网上更为人熟知的名字是 [CDHCHAOREN](https://makerworld.com.cn/zh/@cdhchaoren)——设计可打印的遥控工程机械：挖掘机、叉车、坦克。官微宏在网上看到这些作品，一方面惊讶于机械设计已经做到这个程度，另一方面也看到控制电子拖了后腿。

当时模型设计者能买到的遥控电子，其局限跟模型本身毫无关系。摇杆报出来的几乎只是一个方向，而不是成比例的位置，于是大臂只能"抬起／放下"，却做不到**轻轻地**动。通道被固定绑死在特定功能上。想加灯光或音效，就得再叠一块别扭的扩展板。而且这一切都无法编程——一条精心设计了减速比的挖掘机大臂，最后只能像玩具一样被驾驶。

于是官微宏主动联系了他，提出自己和方圣源可以做一套更配得上这些机械的方案。MeshMass 就是这么来的：发射器如实送出成比例的读数；接收机把电机驱动直接做在板上；而在编程模型上，一辆车的行为就写在这辆车自己身上。

把硬件做好只解决了一半的问题。陈东浩是设计师，不是程序员，也不是电子工程师，而他还要照顾自己的客户——那些买了模型、之后想升级固件或者想改改操控手感的人。按传统做法，答案就是把源码丢给对方：装工具链、配 IDE、改代码、重新编译。这里的每一步都可能卡住，而另一端的人是模型买家、小学生，以及刚买了 3D 打印机、想和孩子一起做点好玩东西的家长。没有人是为了调试编译环境才来的。

这就是为什么平台本身是产品的一部分，而不是一个附属品。工具链和固件内核都放在服务器上：打开网页、选一课、改个数字、编译、烧录。不用安装、不用注册、不用配置——于是"喏，链接在这儿"就可以是全部的技术支持说明。

最初促成这件事的组合——一个人设计机械，一个人负责电子与代码——至今仍是那些有意思的作品的诞生方式。如果你是模型设计者，电子这一侧的内容都记录在这里，[课程也是开源的](/zh/MeshMass-RX4M4S#参考示例)；把设计带来，其余的都可以学会。

## 设计理念

### 为什么选择基于代码的编程？

传统的遥控解决方案存在两个主要缺陷：

**A. 复杂的开源硬件方案**
- 需要深厚的电子知识进行组装和调试
- 涉及多个组件（Arduino、RF模块、电机驱动器、电源调节）
- 需要复杂的软件工具链（Arduino IDE、平台配置）
- 初学者和爱好者的学习曲线陡峭

**B. 昂贵的“可定制”遥控器**
- 依赖复杂的菜单系统，用户体验差
- 仅限于预定义的混控选项
- 价格昂贵（$200-500+ 提供类似功能）
- 无法实现真正自定义的行为

**MeshMass：两全其美**
- **简单**：使用简洁的C代码，专注于输入/输出映射的API
- **强大**：无需硬件复杂性即可获得遥控控制的编程灵活性
- **经济**：以爱好者的价格获得专业级控制
- **易用**：基于Web的编辑器，无需复杂工具链安装
- **示例驱动**：提供全面的工作代码示例和教程库，涵盖常见用例

## 竞争优势

### 空间效率与集成
- **单PCB解决方案**：40mm × 60mm RX4M4S 替代接收器 + 4个电调 + 凌乱的布线
- **传统方法**：多块板子堆叠，布线复杂，难以安装在紧凑的3D打印空间内
- **优势**：干净集成到设计模型中，无需重新设计车身以适应组件

### 系统总成本优势
- **MeshMass TX6A4D + RX4M4S**：比单独的Flysky发射器更便宜
- **传统方案**：Flysky发射器（$30+）+ 接收器（$30）+ 4个电调（$40+）+ 布线 = $100+
- **优势**：以爱好者的价格点获得专业级控制

### 编程易用性
- **基于文本的C语言**：揭示底层数学（例如 `150 + centered(4, 0) * 2 / 5`）
- **教育价值**：用户看到公式控制物理运动
- **对比可视化编程**：图形化积木掩盖数学，简单逻辑占用更多屏幕空间
- **框架编程方法**：底层代码（RTOS、RF、驱动程序）预构建；用户只需编写映射逻辑

### 可重用性与灵活性
- **轻松重新烧录**：模块可以在不同打印项目间移动
- **传统遥控器**：需要复杂的菜单导航或物理重新布线
- **一套固件、可配置的板子**：接收机程序里的两个开关决定共享排针是驱动舵机、灯带还是音频模块——默认 4 电机 + 4 舵机，两个配件都装上时为 4 电机 + 1 舵机

### 易于视觉调试
- **无需执行器的固件验证**：验证代码而无需连接示波器或逻辑分析仪（这些设备可能功能强大但危险）
- **发射器侧状态显示**：电池电压和信号强度显示在发射器OLED上（用户握在手中）
- **接收器侧输出调试**：通道值、电机输出和舵机输出显示在接收器OLED上（用于映射验证）
- **使用模式对齐的设计**：发射器在手用于系统状态监控，接收器远程用于输出行为验证
- **即时反馈**：学生实时看到代码更改如何影响物理输出

## 系统架构

### 关注点分离
MeshMass 系统在发射器与接收器之间划分职责，但**并不对等**——这种不平衡是有意的：

- **TX6A4D（发射器）**：读取物理输入，并把它们原样转发到 16 个无线通道上。一套程序，所有遥控器都一样。
- **RX4M4S（接收器）**：解释这些通道，驱动全部物理输出——电机、舵机、灯光、声音。一个作品的行为就住在这里。

原因很简单，就在于这两端各自「是什么」。遥控器永远是同一副样子：两根摇杆、两个旋钮、四个按键，握在你手里。而接收机每次都被装进不同的机器——坦克、挖掘机、叉车、自卸车——每一种都想要自己的混控、自己的限位、自己的灯光和引擎声。

灯带和音频接口让这一点更加明显。接收机不只决定摇杆如何变成履带速度，还决定什么时候亮刹车灯、什么时候改变引擎声。把这些行为拆到两端，就意味着改一辆车要动两块板上的两个程序。

所以发射器不做任何决定。它只负责测量和转发；解释权归接收机。遥控器烧录一次，就能配合你之后做的每一辆车——而当你要改一辆车时，你改的就是那辆车。

### 基于通道的通信
- **16个无线通道**：单字节在设备之间传输
- **线路上传的是原始读数**：发射器把每个模拟输入按无符号 `0`-`255` 发出（约 `128` 居中）；居中、死区、缩放与混控都是接收机的工作
- **灵活路由**：任何输入都可以通过简单代码映射到任何输出
- **实时性能**：50Hz更新速率匹配舵机刷新，最低延迟无线通信

### 典型信号流
```
TX6A4D 摇杆 → getStick() → setChannel() → 无线传输
                                                              ↓
RX4M4S 接收 → getChannel() → setMotor()/setServo() → 电机/舵机
```

所有映射均可通过 MeshMass 在线平台 [meshmass.com](https://meshmass.com)（全球访问）或 [meshmass.y77.cc](https://meshmass.y77.cc)（中国大陆访问）配置。

## 框架编程方法

### 预构建基础
- **底层代码已编写**：RF通信、时序、硬件驱动程序
- **内置安全功能**：连接丢失处理、安全值、硬件保护
- **实时操作系统**：管理多个任务，无需用户干预

### 专注于应用逻辑
用户只需编写对其特定车辆重要的代码：
- 发射器上的输入到通道映射
- 接收器上的通道到输出映射
- 复杂行为的混合函数
- 无需理解无线协议或PWM时序细节

### 开发工作流程
**传统开源硬件方法：**
1. 研究组件（2-4小时）
2. 订购零件，等待发货（3-7天）
3. 组装硬件，调试连接（4-8小时）
4. 编写固件，调试RF通信（6-12小时）
5. 测试和优化（2-4小时）
**总计：15-35小时，耗时3-7天**

**MeshMass方法：**
1. 插入模块和USB烧录器（2分钟）
2. 选择预构建示例或在Web编辑器中修改代码（5-15分钟）
3. 烧录和测试（1分钟）
4. 按需优化代码（5-15分钟）
**总计：10-30分钟**

*meshmass.com上提供全面的示例和教程，大多数用户可以在几分钟内找到适合其特定用例的工作代码。来自3D打印社区的初学者通常可以找到与其车辆设计匹配的即用模板。*

## 教育价值

### 数学变得生动
- **变量与函数**：学生看到 `getChannel(0)` 如何读取发射器发来的摇杆位置
- **数值范围与符号**：摇杆送来的是无符号的 `0`-`255`；减去中点后变成带符号的 `-127`-`127`，此时**符号本身就是方向**
- **坐标系**：一根摇杆的 X 轴与 Y 轴变成两个可以各自参与运算的数
- **代数运算**：arcade 转向就是两行式子——`左 = Y - X`、`右 = Y + X`——学生可以推理为什么一侧履带加速、另一侧就减速
- **条件逻辑**：使用 `if (getChannel(6)) { setMotor(0, 0); }` 实现安全功能
- **缩放与变换**：用除法限制最高速度，或把混控结果归一化，使满杆时不会削顶

### 即时物理反馈
- 代码更改 → 即时车辆响应
- 通过观察车辆移动进行调试
- **视觉调试**：在OLED显示屏上实时观察输入和通道值更新
- 通过因果关系学习编程
- 代码与物理运动之间没有抽象层

### 渐进式学习路径
1. **从预烧录套件开始**：套件设计师提供即用固件
2. **修改现有示例**：调整参数和混合行为

## 配对系统

MeshMass使用安全的一对一配对系统在发射器和接收器模块之间建立独占无线连接。配对系统确保可靠通信并防止附近其他设备的干扰。

### EEPROM存储

配对信息存储在 **EEPROM**（电可擦可编程只读存储器）中，这是一种非易失性存储器，即使断电也能保留数据。一旦发射器和接收器配对，它们的连接信息会在电源循环和重启后保持。这意味着您无需每次使用时重新配对设备——当两个设备通电时，已建立的连接会自动恢复。

### 一对一独占配对

MeshMass配对是**双向且独占的**：
- 当发射器与新接收器配对时，它将失去对之前配对的任何接收器的访问权限
- 当接收器与新发射器配对时，其之前的发射器将无法再控制它

这种一对一关系确保每个发射器一次仅控制一个接收器，每个接收器仅响应一个发射器。如果您需要同时控制多个接收器，则需要多个发射器模块。

### 配对流程

要将MeshMass发射器与接收器配对：

1. **在第一个设备上进入配对模式**：
   - 按下并按住**配对按钮**超过**5秒钟**
   - OLED屏幕将指示配对模式（通常显示“PAIRING”或类似信息）

2. **在第二个设备上进入配对模式**：
   - 当第一个设备处于配对模式时，按下并按住第二个设备上的**配对按钮**
   - 该设备也将进入配对模式并有相应的屏幕指示

3. **自动身份交换**：
   - 当两个设备都处于配对模式且在无线范围内时，它们会自动交换身份信息
   - 此过程通常在几秒钟内完成

4. **返回正常操作**：
   - 两个设备自动退出配对模式并返回正常操作
   - OLED显示屏恢复显示输入值和通道数据
   - 设备现已配对并准备使用

**取消配对**：如果设备处于配对模式，再次按下配对按钮将终止配对过程。由于没有新的配对信息被存储，先前的配对记录保持完整，当设备返回正常模式时将继续使用。

*有关设备特定的配对按钮位置和详细信息，请参阅各个产品页面。配对按钮在PCB上标记为“PAIR”，由固件控制——不能重新编程用于其他功能。*

## 固件升级

我们建议发射器使用 **TX6AX**、接收机使用 **RX4MX**。这是当前的固件，所有课程和示例都是针对它们编写的。

请把两端烧录到同一代固件上。更早的固件传输的是带符号的 `-127`-`127` 通道值，并且在发射器一侧完成居中与混控；两代混用会得到一条能连上、但行为不正确的链路。那一代固件对已经在用的板子仍然提供支持，但已不再推荐使用——新的课程与示例只针对 TX6AX 和 RX4MX。

**配对不受升级影响。** 配对信息保存在 EEPROM 中，重新烧录后依然有效，已配对的一套设备可以继续使用——不需要重新配对。

如果你曾针对早期 API 写过自己的代码，请按下表迁移。

**迁移接收机程序：**

| 之前 | 现在 |
|---|---|
| 按配件组合挑选固件版本（`RX4M3S1N`、`RX4M1S1N1A` 等） | 一套固件；在 `app.h` 顶部设置 `AUDIO_ON_SM1_SM2` 与 `NEO_ON_SM3` |
| `getChannel()` 返回已居中的带符号 `-127`-`127` | 返回原始无符号 `0`-`255`；摇杆读数请用 [`centered()`](/zh/MeshMass-RX4M4S#摇杆通道的居中处理) 包一层 |
| `setServo()` 的序号是该版本中实际存在的舵机 | 序号是 **SM 排针编号**，因此装了音频模块的配置下舵机是 `0` 和 `3` |
| `neoInit(count)` | `neoSetup(count)` |

**迁移发射器程序**：多数情况下不需要迁移。混控、死区与缩放现在都属于接收机，所以默认的 TX6AX 程序通常就够用了——你原先写在发射器上的逻辑，改写到车辆上即可。
