# Sourcekit® MeshMass TX6A4D

版本: 1.0.0

设计人: Weihong Guan [<span class="mdi mdi-github" style="color: #000;"></span>](https://github.com/aguegu/) [<span class="mdi mdi-twitter" style="color: #1da1f2;"></span>](https://twitter.com/BG5USN), 方圣源，陈东浩

## 概述

Sourcekit® MeshMass TX6A4D 是一款可编程的遥控发射器模块，专为遥控爱好者、STEM教育和3D打印社区设计。它是MeshMass系列中首款经济实惠的可编程遥控解决方案产品。

TX6A4D 配备双摇杆、旋转旋钮和可编程按钮，非常适合为玩具、积木搭建和3D打印车辆构建自定义遥控系统。

![TX6A4D 控制器](/images/MeshMass-TX6A4D/main.jpg)

## 特性

- **双摇杆**: 两个双轴摇杆提供4个模拟输入通道
- **旋转旋钮**: 2个旋钮提供2个模拟输入通道，可编程用于油门、速度或参数调节
- **可编程按钮**: 4个肩部按钮 + 2个摇杆按压按钮支持自定义功能
- **OLED显示接口**: 6针SH1.0连接器支持128x64 SPI OLED（单独出售），显示电池电压、信号强度和原始输入值
- **Type-C充电**: 内置1S LiPo电池充电电路
- **天线选项**: 板载PCB天线 + IPEX-1接口用于外接2.4GHz天线
- **连接丢失报警**: 蜂鸣器在接收器连接丢失时发出警报
- **M2.5安装**: 4个安装孔用于安全固定

## 规格

### 微控制器

TX6A4D 采用南京WCH的CH571F微控制器。该芯片提供核心处理和无线通信能力。

| 组件 | 规格 |
|-----------|---------------|
| MCU | WCH CH571F (CH57x系列) |
| 架构 | 32位 RISC-V (青稞 V3A 核心) |
| CPU 速度 | 48 MHz (典型值) |
| 内存 | 32KB SRAM, 256KB Flash |
| 无线 | 2.4GHz专有协议（原始PHY层实现最低延迟） |
| ADC | 12位, 8通道（6个用于摇杆/旋钮） |
| GPIO | 多个可配置I/O引脚 |
| 外设 | SPI, UART |

CH571F的RISC-V架构提供高效处理能力，而集成的2.4GHz无线电确保可靠的无线通信。TX6A4D利用原始2.4GHz物理层实现实时控制应用中的最低延迟。

### 输入

| 类型 | 数量 | 描述 |
|------|-------|-------------|
| **模拟** (ADC) | 6 | 4个来自摇杆, 2个来自旋钮 |
| **数字** | 4 | 4个可编程肩部按钮 + 2个摇杆按压按钮（并联连接） |
| 系统 | 1 | 配对按钮（固件控制） |

**注意:** 每个摇杆包含内置按压按钮：
- **左摇杆按压**：与左侧边缘按钮（按钮1，`getButton(0)`）并联连接
- **右摇杆按压**：与右侧边缘按钮（按钮4，`getButton(3)`）并联连接 |

## 编程

TX6A4D可通过[MeshMass在线平台](https://meshmass.com)进行编程。用户可以：

- 将摇杆轴、旋钮和按钮映射到输出通道
- 创建自定义控制混合（例如坦克转向、起重机控制）
- 配置按钮行为实现特定功能

编程通过网页浏览器使用MeshMass USB烧录器（单独出售）完成。CH571F运行预构建的固件框架处理底层RF通信，而用户专注于应用级输入映射逻辑。

> **注意**: TX6A4D的USB-C端口仅用于充电。固件烧录需要单独的USB烧录器。

## 固件框架

TX6A4D运行预构建的固件框架，该框架处理底层硬件操作，同时为应用编程提供简单的API。固件框架的关键方面包括：

### 通道系统
固件定义了16个有符号字节（-127至127）作为无线通道。这些通道构成发射器和接收器之间的通信桥梁。值-128被固件避免使用，以实现清洁的方向反转（-127至127提供对称范围）：
- 通道 0-5：通常映射到模拟输入（摇杆、旋钮）
- 通道 6-15：可用于自定义映射（按钮、逻辑、混合）

**模拟输入映射** (通过 `getStick(n)`):
| 索引 | 物理输入 | 描述 |
|------|----------|------|
| 0 | 右摇杆 X轴 | 右摇杆左右移动 |
| 1 | 右摇杆 Y轴 | 右摇杆上下移动 |
| 2 | 左摇杆 Y轴 | 左摇杆上下移动 |
| 3 | 左摇杆 X轴 | 左摇杆左右移动 |
| 4 | 旋钮1 (左) | 旋转旋钮，通常用于油门 |
| 5 | 旋钮2 (右) | 旋转旋钮，通常用于参数调节 |

**数字输入映射** (通过 `getButton(n)`):
| 索引 | 物理输入 | 描述 |
|------|----------|------|
| 0 | 按钮1 (左侧边缘) | 可编程肩部按钮 + 左摇杆按压 |
| 1 | 按钮2 (左侧中间) | 可编程肩部按钮 |
| 2 | 按钮3 (右侧中间) | 可编程肩部按钮 |
| 3 | 按钮4 (右侧边缘) | 可编程肩部按钮 + 右摇杆按压 |
| - | 配对按钮 | 系统按钮（固件控制） |

**注意:** 摇杆按压按钮与肩部按钮并联连接：
- **左摇杆按压**：激活 `getButton(0)`（与左侧边缘按钮相同）
- **右摇杆按压**：激活 `getButton(3)`（与右侧边缘按钮相同） |

### 默认应用程序代码
框架提供简单的API用于读取输入和设置通道。用户可以完全灵活地映射输入到通道，实现复杂的控制行为。以下是一个展示各种映射技术的示例：

```c
#include "app.h"

// 需要在loop()调用之间保持值的变量应声明为全局变量
// 或在loop()内部使用'static'关键字声明
static int button2_was_pressed = 0;  // 跟踪按钮2按下状态

void loop() {
  // 示例1: 直接映射 - 摇杆0控制通道0
  setChannel(0, getStick(0));

  // 示例2: 反向映射 - 摇杆1控制通道1，方向反转
  setChannel(1, -getStick(1));

  // 示例3: 缩放映射 - 摇杆2控制通道2，灵敏度减半
  setChannel(2, getStick(2) / 2);

  // 示例4: 混合控制 - 使用摇杆3进行辅助控制
  setChannel(3, getStick(3));

  // 示例5: 死区处理 - 忽略小的摇杆移动
  if (abs(getStick(4)) > 10) {
    setChannel(4, getStick(4));
  } else {
    setChannel(4, 0);
  }

  // 示例6: 按钮控制的通道6 (递增/递减)
  if (getButton(0) && getChannel(6) < 127) {
    setChannel(6, getChannel(6) + 1);
  }
  if (getButton(1) && getChannel(6) > -127) {
    setChannel(6, getChannel(6) - 1);
  }

  // 示例7: 按钮锁存 - 在按钮按下时切换通道7
  if (getButton(2) && !button2_was_pressed) {
    setChannel(7, -getChannel(7)); // 在正负值之间切换
    button2_was_pressed = 1;
  }
  if (!getButton(2)) {
    button2_was_pressed = 0;
  }

  // 示例8: 复杂混合 - 组合多个输入用于坦克转向
  // 右摇杆和左摇杆垂直轴平均用于差速驱动车辆
  setChannel(8, (getStick(1) + getStick(2)) / 2);

  // --- 高级混合示例 ---

  // 示例9: 指数响应用于精细控制
  // 平方摇杆值（保留符号）实现非线性响应
  int stick_val = getStick(5);
  int sign = (stick_val > 0) ? 1 : ((stick_val < 0) ? -1 : 0);
  setChannel(9, (stick_val * stick_val * sign) / 127);

  // 示例10: 双按钮安全锁存 - 需要两个按钮同时按下
  // 按钮3作为安全开关，必须按住同时按钮2触发动作
  if (getButton(3) && getButton(2)) {
    setChannel(10, 127);  // 安全+触发按下时全速前进
  } else {
    setChannel(10, 0);    // 否则停止
  }
}
```

### API 函数
- `getStick(n)`：返回模拟输入 `n` (0-5) 的有符号字节值 (-127 到 127)。值-128被固件避免使用，以实现清洁的方向反转。
- `getButton(n)`：返回数字按钮 `n` (0-3) 的整数值 0（未按下）或 1（按下）
- `getChannel(n)`：返回通道 `n` (0-15) 的当前值
- `setChannel(n, value)`：将通道 `n` 设置为 `value` (-127 到 127)

**状态持久性**：需要在 `loop()` 调用之间保持值的变量应声明为 `static` 在 `loop()` 内部或作为全局变量在函数外部声明。

**标准库**：常见的C标准库函数如 `abs()` 可用于数学运算。

API支持灵活的映射：
- **直接映射**：`setChannel(0, getStick(0))`
- **反向方向**：`setChannel(1, -getStick(1))`
- **缩放灵敏度**：`setChannel(2, getStick(2) / 2)`
- **死区处理**：基于输入阈值有条件地设置通道
- **按钮锁存**：使用状态变量在按钮按下时切换通道
- **按钮递增/递减**：通过按钮按下调整通道值
- **指数响应**：非线性映射用于精细控制（例如 `(摇杆值*摇杆值)/127`）
- **双按钮安全**：要求多个按钮同时按下用于安全关键功能
- **复杂混合**：通过数学运算组合多个输入

### 固件管理的功能
框架自动处理多个系统功能：
- **OLED显示**：显示电池电压、无线信号强度和原始输入值
- **蜂鸣器**：提供连接丢失警报和系统反馈
- **无线通信**：管理2.4GHz数据包传输与自动跳频
- **电池管理**：监测电压并提供低电量警告

这种分离让用户能够专注于应用逻辑（通道映射），而固件处理硬件复杂性。

## 系统架构

MeshMass系统将发射器和接收器的关注点分离：

- **TX6A4D (发射器)**: 将物理输入（摇杆、旋钮、按钮）映射到无线通道
- **RX4M4S (接收器)**: 将接收到的通道映射到物理输出（电机、舵机）

这种抽象让用户能够专注于特定构建中最重要的部分，而无需担心RF协议细节。
